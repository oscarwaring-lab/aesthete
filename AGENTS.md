# Where the DNA report stands (v3.1, shipped 2026-07-31)

## Evidence bindings

Each of the three graded dimensions — colour, composition, mood — now carries an
optional `evidence: { image_index, reasoning }`, tying the claim to the one
source frame that justifies it. Schema in `src/lib/aesthetic-dna.ts`, enforcement
in `src/app/api/aesthetic-dna/route.ts`.

**`image_index` is 1-based**, counted over the images in the order the model was
shown them, which is the order they are persisted — so the cited frame is
`image_urls[image_index - 1]`. That correspondence is the entire value of the
field, and it is load-bearing in a way nothing else here is: getting it off by
one shows a creator a photograph unrelated to the sentence beside it. The `- 1`
lives in exactly one place per side (`resolveEvidence` in
`src/components/DnaReport.tsx`); don't scatter it. `uploadSourceImages` **breaks**
rather than continues past a failed upload, precisely to preserve the ordering —
a gap would silently re-index every frame after it. Don't "fix" that loop into a
`continue`.

The binding is **optional in the schema, mandatory in the prompt**. The model is
told to attribute every dimension; the schema permits it not to. That asymmetry
is deliberate — a report is worth more than an attribution, so failure degrades
instead of throwing. `sanitiseEvidence` drops invalid bindings **per dimension**
(out-of-range index, blank reasoning) without failing the analysis, and the
reasoning pass runs after it so tokens are only spent on bindings that survived.

`MAX_STORED_IMAGES` is now `MAX_IMAGES` (12) rather than 4, so every analysed
frame persists and any valid binding resolves. Rows written before this change
kept only the first 4 of 12 — a legacy v2 binding against frame 9 has nothing to
resolve to, which is why `resolveEvidence` treats an unresolvable frame as a real
case and not a defensive one.

Evidence reasoning is generated by a **dedicated pass at
`EVIDENCE_REASONING_TEMPERATURE = 0.2`**, isolated from the main analysis at 0.4.
Two temperatures on purpose: the analysis wants some range, the attribution wants
none.

## Share page and the evidence spread

`/share/[slug]` sits on a reactive specimen plate graded from `palette[0]`, with a
dynamic OG image. New files: `src/lib/share-plate.ts`, `src/lib/share-profile.ts`,
`src/app/share/[slug]/opengraph-image.tsx`.

`DnaReport.tsx` is an alternating editorial spread — Plate I/II/III for
colour/composition/mood — pairing each claim with its cited frame and reasoning,
with the codified reference and contact sheet below. It is a shared component, so
the rebuild lifted the share page and the dashboard report together; changes here
land in both, and both need looking at.

It degrades in three tiers, and all three are live in production data:

1. evidence resolves → full spread;
2. a dimension's evidence is missing or unresolvable → that dimension renders as
   a text section, the others keep their plates;
3. no evidence anywhere (legacy v2/v1) → the original dense layout, verified
   HTML-identical to what those rows rendered before, with one deliberate
   exception (below).

Tier 3 is the compatibility guarantee. If a change to the shared component alters
the no-evidence output, that is a regression against every report already shared.

The one sanctioned departure is the **source-material thumbnail grid**. The old
`flex` row gave each thumbnail `w-full`, so at a 360px viewport four of them each
tried to take the full card width and blew out of it. It is now an `auto-fit`
grid with tracks capped at 120px, which lays out identically wherever four fit on
a line — every viewport those v2 reports were actually read at — and wraps
instead of overflowing when they don't. So it is a clipping fix, not a redesign:
if you diff tier 3 against an old render, expect this one difference and leave it
alone. The reasoning is restated at the grid itself in `DnaReport.tsx`.

## Settled: the evidence-reasoning voice — do not re-derive

gpt-4o's caption prior on evidence reasoning **cannot be defeated by temperature
or word-bans**. Both levers were measured and are spent: temperature 0 regressed,
and adding word-bans made the output worse rather than better. Structural rules
hold where word-bans don't. v3.1 — temperature 0.2 plus a two-sentence structural
rule — is the ceiling for prompt-only work on this. Re-running that experiment
will cost tokens and reproduce the same answer.

`PROMPT_VERSION` v3.1 is a voice change only; the schema is byte-identical to v3.
It earns a version so a row's register can be read off `prompt_version` without
opening the JSON.

# Deferred

Known and deliberately not done. None are urgent; none are quick.

- **Vary the "You… / This…" cadence in evidence reasoning.** The repetition is
  caused by the two-sentence structural rule — the same rule that holds the voice
  together and is the only lever that survived the experiments above. Loosening
  it without losing the voice needs thought, not a tweak.
- **Improve the creative brief section.**
- **`--card-muted` light-mode contrast is 3.5:1, below AA.** Used by the summary
  and section labels on both layouts. It is a shared token, so fixing it ripples
  into legacy v2 reports (tier 3 above) — needs its own pass with those rendered
  alongside.
- **Export resolution drops to ~0.85× on the taller spread.** The `MAX_SIDE` cap
  in `src/lib/export-image.ts` clamps the retina `SCALE` once the spread grows
  tall enough. Only meaningfully testable against a real DM send, so it is
  parked until there is one.

# Build gotchas

Two toolchain traps that both present as "the styles are just gone", and neither
produces an error. Read these before debugging missing CSS.

## `backdrop-filter` must be UNPREFIXED only

Hand-writing a `-webkit-backdrop-filter` declaration in `globals.css` suppresses
the unprefixed `backdrop-filter` in this Tailwind v4 / Lightning CSS pipeline, so
every Liquid Glass panel renders with its translucent fill and **no blur** in
modern Chrome and Firefox. Write only `backdrop-filter:` and let the toolchain
auto-prefix for old Safari.

Verify with `getComputedStyle(panel).backdropFilter` — it must report a real
`blur(...)`, not `none` — and check the compiled CSS carries both forms. The full
note lives beside the rules it governs, in the `.studio` and `.share` block
headers in `src/app/globals.css`.

## Never run `npm run build` while `next dev` is live

Both write to the same `.next` directory, and the production build empties the
dev CSS chunk. The dev server keeps serving happily, but `globals.css` arrives
with **zero rules**: glass panels lose their fill, `.share` / `.studio` / `.landing`
scoped styles vanish, and `getComputedStyle` reports values as though the
stylesheet were never loaded (e.g. `background: rgba(0, 0, 0, 0)` on an element
that plainly sets one).

Nothing warns you, and the source is fine — so it reads like a CSS bug and sends
you chasing specificity or cascade problems that don't exist. It also silently
invalidates any browser verification done after the build.

Stop the dev server before building. To recover:

```bash
rm -rf .next
```

then restart `next dev` and re-take any measurements from before the build.
